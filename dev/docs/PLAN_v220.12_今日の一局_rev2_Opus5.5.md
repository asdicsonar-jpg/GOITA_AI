## 3. 設計（推奨どおりにした場合。推奨なしの論点は (a) で書き、裁定で変われば直す）

### 3-1. 日付と種（族 `D-a`）

- `dailyInfo(now)`（純粋な関数・引数は時刻のミリ秒）:
  - 日付: T-2 (a) なら `new Date(now + 9 時間).toISOString().slice(0, 10)`、(b) なら端末の日付（`today()` と同じ式）。
  - 種の候補 k = 0, 1, 2, …: `"goita-daily:" + 日付 + ":" + k` の FNV-1a 32 ビット（文字列の UTF-16 の符号単位ごと・`charCodeAt`。今の文字列は ASCII だけ）を `% 2147483647`（0 なら 1）。
  - **その種の最初の配り `G.dealOnce(G.mulberry32(種))` で、全員の し が 4 枚以下になる最初の k を使う**（2-5・2-6 と同じ考え。席のティアに依らない）。第二読者の実測では、最初の配りに し 5 枚以上がいるのは約 17%（手役 1.96%・人の相談 3.5%・AI の配り直し 10.8%・AI の続行 0.4%）なので、k はほとんど 0〜2。上限 k < 64（超えたら止めて案内する。起きない見込み・D1 で 1 年分を測る）。
  - 親: `G.SEATS[(種 >>> 3) % 4]`。`app.rng` を使わない。
- これで今日の一局には手役・五し相談・配り直しが来ない（M-1・S-4 を元から閉じる）。

### 3-2. 開始画面（族 `D-b`・T-6 (a)）

- `#setup-go` の `.actions` に `<button class="btn" id="btn-daily">今日の一局</button>` を足す（「観戦」の後ろ）。
- その下に 1 行（`<p class="desc" id="daily-note">`）。文は案（Sonar に見ていただく）:
  - まだ打っていない日: 「日ごとに変わる配りを 1 局だけ打ちます（連続の記録は取りません）。」
  - 打った日（T-4 (a)）: 「今日の一局は打ちました（勝ち・30点）。もう一度打てますが、成績には入りません。」
  - 途中で切れた日（T-7b (i)(ii)）: 「今日の一局は途中でやめました。もう一度打てますが、成績には入りません。」
- 開始画面を描き直す所（起動・`stopToSetup`）で 1 行を更新する。

### 3-3. 始め方（族 `D-c`）

- `btn-daily` → `enterGame(false, true)`。`enterGame`（L27793）の中で:
  - `readSetup(false)` の直後・助言の確かめ（L27800）の前に、`humanSeat` が無ければ `app.tiers.S = "human"; app.humanSeat = "S"`（今日の一局は自分が打つ）。※ `readSetup(false)` は席が AI のとき `clearHumanLearningBoth("S")`（L27745）を呼ぶ。今日の一局ではその後に人の席にするので、S 席の学習の残りは消えたまま始まる（今の「観戦の後に打つ」と同じ）。
  - 中の `newMatch()` 3 か所（L27808・L27817・L27822）を `newMatch(daily ? {daily: dailyInfo(Date.now())} : undefined)` にする。
- `guardNewMatch` は通さない（保存を消さないため・T-7 (a)）。
- **`newMatch(opts)`**（写しを作らない・第二読者 S-12）: 引数が無ければ今と同じ式。`opts.daily` のときだけ、`deleteMatchProgress()` を飛ばし、`matchSeed` と親を `dailyInfo` から取り、`app.daily = {date, replay, done: false}` を立て、ログと棋譜の見出しに「今日の一局（日付）」を書く。引数が無いときは `app.daily = null`。
- `stopToSetup`・`resumeSavedMatch`・研究モードの開始（L23748〜）で `app.daily = null`。

### 3-4. 終わり方（族 `D-d`）

- `onGameOver` の頭で `app.daily` なら `app.daily.done = true`。先取点に届いたか（`over`・L25609）は常に偽（**保存を消さない**・2-4）。帯は「振り返り」「この局を共有」（悪手の振り返りなど今ある物も）「設定へ戻る」（`stopToSetup`）。「次の局へ」「結果を見る」は出さない。流局の帯（L25594）も同じ。
- `closeReviewToGame`・`endPractice` の「次の局へ」「結果を見る」も、`app.daily` のときは「設定へ戻る」。
- 安全網（来ないはずの道）: `onSpecialYaku` の頭で `app.daily` なら `done = true` にして帯は「設定へ戻る」だけ（得点の加算と `showMatchEnd` をしない）。`showMatchEnd` の頭で `app.daily` なら何もしない。`startGame` の頭で `app.daily && app.daily.done` なら toast「今日の一局は終わりました」を出して `stopToSetup()`。

### 3-5. 成績（族 `D-e`・T-5 (a)・T-5b (a)）

- 1 回目: 今と同じ（普通の局）。局の rec と `career`・`coachHistory` の項目に `daily: 日付` を足す（その場のメモリだけ。保存の形は変えない）。
- 2 回目から（`app.daily.replay`）: L25545〜25571 のうち、学習（`auditConvTrust`・`auditOppProfile`・`auditTblConformity`・`sampleLearnTelemetry`）・`pastMaybeAdd`・`matchRecs.push`・`coachHistory` と `career` への追加・`gradOnGameFinished` を飛ばす。振り返りに要る `computeCoach`・`computeSignals` はする。卒業の試しの途中なら toast「今日の一局の2回目は、卒業の試しに数えません」（1手戻すの L19953 と同じ形）。
- 振り返りから途中に戻す（`resumeFromMove`）: `app.daily` の局（rec に `daily`）なら、読込の局と同じ `startPractice` へ回す（T-5b (a)）。練習の終わりは `endPractice` →「設定へ戻る」。
- `resumeFromMove` の filter（L27342〜27343）は `daily` の項目を残す（同じセッションで保存を再開した後、番号が重なった勝負の巻き戻しで今日の一局の成績を消さない・第二読者 S-11。セッションをまたぐ重なりは今のまま）。

### 3-6. 保存しない（族 `D-f`・T-7 (a)）

- `matchSaveAllowed()` に `&& !app.daily` を足す。

### 3-7. 印の保存（族 `D-g`）

- 新しいキー `goita_daily_v1` = `{d: "YYYY-MM-DD", r: null | {w: true|false, pts, draw: true|false}}`。**最後の 1 日分だけ**を上書きする（連続日数を作れる履歴を持たない）。
- T-7b の答えの時点で `{d, r: null}` を書く。1 回目の局が終わったら `r` を書く。**`app.daily.date` と保存の `d` が同じときだけ**書く（日付をまたいで打ち終えても、次の日の印にしない）。
- `replay` は、始める時点で保存の `d` が今日の日付と同じなら真。
- 古い版はこのキーを読まないので壊れない。読めない値は無いものとして扱う。

### 3-8. 盤の上の帯（族 `D-h`）

- `startGame` の `modeBanner(null)`（L24480）の後で、`app.daily` なら `modeBanner("<b>今日の一局</b><span>9月28日</span>")`。2 回目は `<span class="dim">2回目・成績には入りません</span>` を足す。
